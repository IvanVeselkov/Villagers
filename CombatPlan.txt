ПЛАН РЕАЛИЗАЦИИ БОЕВОЙ СИСТЕМЫ (ВАРИАНТ 2 - СЕРВЕРНЫЙ ПОИСК ПОПАДАНИЙ)
ЦЕЛЬ: Единая боевая система под Mirror (игроки vs игроки, игрок vs NPC), с заделом под ближний бой, лук, посохи.
ПРИНЦИП: АВТОРИТЕТ СЕРВЕРА. Весь урон считается ТОЛЬКО на сервере.

1. БАЗОВАЯ АРХИТЕКТУРА
Нужна единая точка входа урона. IDamageable интерфейс + общая логика.
Реализовать на: HealthSystem (игроки), NPCHealth (NPC).

2. КЛЮЧЕВЫЕ ИЗМЕНЕНИЯ
AttackManager: if (!isLocalPlayer) return; ввод -> [Command] CmdAttack
CombatBase: на сервере Physics.OverlapSphere для melee, Raycast для bow/staff
HealthSystem: реализовать IDamageable, урон только через [Server]
HitBox: оставить как опциональный маркер или искать IDamageable по родителю

3. ПОШАГОВЫЙ ПЛАН
Шаг 1: Создать Assets/Scripts/Combat/, IDamageable.cs, AttackData.cs (SO), CombatBase.cs
Шаг 2: Переделать HealthSystem под IDamageable
Шаг 3: AttackManager + CombatBase - OverlapSphere на сервере
Шаг 4: NPCHealth + поддержка NPC
Шаг 5: Задел под лук/посох

4. НЮАНСЫ
- Весь урон только сервер
- LayerMask для фильтрации
- Кулдаун на сервере
- Анимация локально + синхронизация при необходимости
- NetworkIdentity для игроков и желательно для NPC
- Игнор своего коллайдера

5. РЕКОМЕНДАЦИИ
Сначала только ближний бой, протестить на Host/Client, потом NPC и дальний бой.
Главный принцип: Клиент запрашивает -> Сервер проверяет и применяет.
